# Vehicle catalog screen: live API integration

Status: the catalog screen runs on the live API. This finishes the frontend work for sub-phase 1E.

| #   | Decision                                                                                                                                                                                                                                | Why                                                                                                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The grid reads the list endpoint (search, category, status, page) and shows each model's starting price, counts and Main image from the summary. The full model, with versions, colors and images, is read fresh when its window opens. | A list of cards should not download every image of every color; the detail needs current data.                                            |
| 2   | Every catalog write invalidates the whole catalog cache, so lists and the open detail are read again from the server.                                                                                                                   | The catalog is small and edited rarely. Refetching can never show data the server did not accept, which patching the cache by hand could. |
| 3   | Creating a model is one form: model data, first version and first color, plus the Main view image, sent as one multipart request. After creating, the new model's detail opens so the remaining images can be added.                    | The backend refuses a model without them, and the person lands where the next step is.                                                    |
| 4   | Files are checked in the browser (type, 5 MB, not empty) before upload, with a clear message; the server checks again from the file's real bytes. Prices are checked and sent as two-decimal strings.                                   | Fast feedback, with the server staying the authority.                                                                                     |
| 5   | The color window shows all six viewpoints. Uploading to an empty slot adds an image, uploading to a filled one replaces it, and the Main view has no remove button.                                                                     | Mirrors the backend rules, so the interface never offers an action that will be refused.                                                  |
| 6   | Managers and Admins can edit, add, archive and reactivate; Admins can also delete, always with a written reason. Advisors get a read-only catalog of active entries (they never see the status filter), and the API enforces the same.  | Permission matrix FR-034/035.                                                                                                             |
| 7   | Archiving a model asks for confirmation; archiving a version or color is one click with a toast. The "last active version/color" and "incomplete model" refusals appear as the server's own message.                                    | Hiding a model affects the sale form, so it deserves a confirmation; the rest are easily undone.                                          |
| 8   | Demo mode keeps the original sample catalog, untouched, as `DemoCatalogPage`.                                                                                                                                                           | The offline demo and its tests keep working.                                                                                              |
| 9   | `Field` now links labels, hints and errors with `htmlFor` and `aria-describedby` and marks invalid controls.                                                                                                                            | An error shown inside a label made a field's accessible name read like a sentence. This helps every form in the app.                      |
| 10  | The list pages no longer fire a request for the old page when a search or filter changes.                                                                                                                                               | Found while testing: the page reset used an effect, which cost one wasted call.                                                           |

## Open items

- Images are not cropped or resized. If photos come straight from phones, add a size limit on dimensions or resize on the server.
- Models are listed twelve per page. If the catalog stays small, a single page with search is enough.
