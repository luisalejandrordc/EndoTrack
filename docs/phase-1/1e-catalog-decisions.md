# 1E vehicle catalog: implementation decisions

Status: the catalog module, the file-storage adapter (Cloudflare R2, local disk, in-memory) and the deletion queue are implemented and tested. This completes backend sub-phase 1E.

| #   | Decision                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | A model is created together with its first version, first color and that color's Main view image, in one multipart request (`data` JSON part plus `mainImage` file). Adding a color works the same way.                                                                 | The database refuses a model without them, so there is no valid half-created state to expose.                                                                                                      |
| 2   | The file is stored before the database transaction; if the transaction fails the file is deleted again. A committed row therefore always points at a file that exists.                                                                                                  | The opposite order could leave rows pointing at nothing, which is visible to users. An orphan file is harmless and logged.                                                                         |
| 3   | The image type comes from the file's bytes, never from the client's `Content-Type` or file name. Only JPEG, PNG and WebP, at most 5 MB.                                                                                                                                 | A client-declared type can be anything. The body is also cut off while streaming, so an oversized upload is never held in memory.                                                                  |
| 4   | Every upload gets a new storage key (`catalog/colors/<color>/<viewpoint>-<image id>.<ext>`). A replacement updates the row to the new key and queues the old file for deletion.                                                                                         | A new address defeats browser and CDN caches, and two uploads of one viewpoint cannot overwrite each other.                                                                                        |
| 5   | Deleting old files goes through `storage_deletions`: the row is written in the same transaction as the change, the file is deleted after the commit, and a failure stays queued with its error. `storagecleanup.RetryOpen` is the function the scheduled job will call. | A crash or a storage outage never loses a deletion and never fails a request whose business change already committed.                                                                              |
| 6   | Prices are decimal strings in responses (`"35000.00"`) and are parsed as integers of cents. Requests accept a JSON number or a string; more than two decimals, zero, negatives and exponents are field errors.                                                          | No floating-point money anywhere.                                                                                                                                                                  |
| 7   | "Last active version/color" is checked in the service, under a lock on the model row, before the database trigger.                                                                                                                                                      | The user gets `LAST_ACTIVE_VERSION` or `LAST_ACTIVE_COLOR` instead of a generic incomplete-catalog error, and two simultaneous archives cannot both win. The trigger stays as the backstop.        |
| 8   | Advisors only ever see active models, versions and colors; an archived model answers 404 to them. Managers and Admins see everything.                                                                                                                                   | FR-034. A sale that already uses an archived entry reads its own snapshot, not the catalog.                                                                                                        |
| 9   | Versions and colors also get `/unarchive`, and models, versions and colors get an Admin-only `DELETE` with a required reason.                                                                                                                                           | The architecture table listed only archive; reactivation and permanent deletion are in the permission matrix, so the routes had to exist. Deletion is refused while any sale references the entry. |
| 10  | `GET /catalog/selectable` is a single call for the sale form: active models with their selectable versions (ordered by price) and colors with Main images. A model with nothing to choose is left out.                                                                  | The form should not stitch together several lists or re-implement the selectable rules.                                                                                                            |
| 11  | Local development and tests keep images in `LOCAL_MEDIA_DIR` and serve them at `/media`; production needs the five `R2_*` values together. Without them, anywhere but local/test, uploads fail with `STORAGE_UNAVAILABLE`.                                              | A missing store must never look like success. A half-set R2 configuration stops the server at startup.                                                                                             |
