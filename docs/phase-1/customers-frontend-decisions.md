# Customers screen: live API integration

Status: the customers screen runs on the live API. Vehicles (catalog) is next.

| #   | Decision                                                                                                                                                                                                                                                           | Why                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | Types come from `openapi.yaml` (`npm run api:types`, flag `--default-non-nullable=false`), and a stale file fails `api:types:check`.                                                                                                                               | The contract is the single source of truth; a field renamed in the backend becomes a compile error here.                 |
| 2   | TanStack Query holds server data. Search, filters, sort and page are sent to the server; nothing is filtered in the browser.                                                                                                                                       | The directory can grow past one page, and Advisors must only ever receive their own scope.                               |
| 3   | The customer list keeps the previous page on screen while the next loads, and the three summary cards use tiny `pageSize=1` requests for the totals.                                                                                                               | No flicker, and the totals stay correct under filters and Advisor scope without downloading rows.                        |
| 4   | Creating a customer starts with a document check: existence lookup first, then Codart (DNI and RUC only). A customer that already exists is offered for editing instead of duplicated. An Advisor who is not linked to it sees only a message with the legal name. | FR-022 to FR-024: no duplicates, and no data leak through the lookup.                                                    |
| 5   | Names filled by Codart are read-only and sent with `nameSource: looked_up`. "Editar manualmente" unlocks them and flips the source to `manual`. Changing the document afterwards clears them.                                                                      | The stored provenance must stay truthful, and a name must never belong to a different document than the one saved.       |
| 6   | Any lookup failure (not found, quota, rate limit, outage) leaves manual entry open and shows the backend's own message.                                                                                                                                            | FR-023. A third-party outage must never block creating a customer.                                                       |
| 7   | An edit sends only the fields that changed plus the version; a changed customer type sends the whole new shape. A version conflict offers "Cargar los cambios" instead of overwriting.                                                                             | Matches the PATCH contract and protects the other person's work.                                                         |
| 8   | Deactivate and reactivate need Manager or Admin; delete needs Admin, a written reason, and fails clearly for a customer with sales. The buttons are hidden for roles that cannot use them, and the API still enforces it.                                          | Permission matrix; the interface follows the rules, it does not replace them.                                            |
| 9   | Demo mode keeps the original sample-data directory, untouched, as `DemoCustomersPage`.                                                                                                                                                                             | The offline demo and its tests keep working.                                                                             |
| 10  | React Router is not added yet.                                                                                                                                                                                                                                     | It touches every screen and the sale flow; it is better introduced as its own step once customers and vehicles are live. |
